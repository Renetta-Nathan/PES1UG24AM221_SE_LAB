# Software Engineering Lab

## Lab 05 – Static Code Analysis

This lab focused on improving the quality, security, and maintainability of the Python program assigned for the Vehicle Service Management System. Static code analysis was performed using Pylint, Bandit, and Flake8 to identify potential programming issues, insecure coding practices, and formatting violations. The identified issues were documented and addressed by modifying the source code, followed by running the analysis tools again to verify the changes.

The lab also involved generating before-and-after analysis reports and maintaining separate Git commits for the changes associated with each static analysis tool.

### Topics Covered

* Static Code Analysis
* Python Code Quality Analysis using Pylint
* Security Vulnerability Detection using Bandit
* Code Style and Formatting using Flake8
* Identification and Classification of Code Issues
* Mutable Default Arguments and Exception Handling
* Secure File Handling and Command Execution
* Code Refactoring and Maintainability
* Before-and-After Analysis Reports
* Git Version Control and Commit Management
* Reflection on Static Analysis

### Tools Used

* Python
* Google Colab
* Pylint
* Bandit
* Flake8
* Git and GitHub

### Analysis Summary

| Tool | Purpose | Result |
|---|---|---|

| Bandit | Security vulnerability analysis | No issues identified in the final scan |
| Flake8 | Python style and formatting checks | No issues identified in the final scan |

### Deliverables

* `vehicle_service.py` – Updated Python source code
* `issues.md` – Documentation of identified issues and their fixes
* `pylint_report_before.txt` and `pylint_report_after.txt`

### Conclusion

This lab demonstrated how static code analysis tools can help identify potential code quality, security, and formatting problems without executing the source code as part of the analysis itself. Using Pylint, Bandit, and Flake8 provided different perspectives on the Python program and helped develop a more structured approach to code review, issue resolution, and verification. The before-and-after reports and Git commits provide a record of the improvements made during the lab.
